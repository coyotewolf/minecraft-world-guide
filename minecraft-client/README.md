# AOI 遊戲內 AI 小助手

Minecraft Java 1.20.1 / Forge 47.4.23 的純客戶端模組。沿用王國飛翼攻略網站的玩家帳號、Cloudflare AI 問答與 Supabase 聊天紀錄，不需要伺服器安裝，也不新增知識庫或 AI 供應商。

## 遊戲聊天室公告（0.1.6）

新版會在進入世界後約每分鐘接收公開公告，支援過期排除、跨重啟去重及斷線退避。管理員從攻略網站控制檯發布，往後不需更新 JAR。詳細操作與效能設計見 [ANNOUNCEMENTS.md](ANNOUNCEMENTS.md)。

## 統一發布與自動更新（0.1.8）

安裝一次後，Windows 每次啟動時背景檢查一次官方簽章版本；關閉遊戲後自動備份並替換，下次啟動生效。可用 `/ai 更新` 立即檢查，或 `autoUpdate=false` 關閉。發布端收成單一命令，詳見 [AUTO-UPDATE.md](AUTO-UPDATE.md)。

## 指令修正（0.1.11）

`/ai older` 顯示本次新載入的全部訊息，沒有更早紀錄時直接提示；最多載入300則。`/ai sources` 只會引用目前對話中已載入且仍存在的回覆，切換或刪除後會更新。更新檔正在等待安裝時，其他更新操作不會覆寫暫存檔。

## 附近實體搜尋（0.1.12）

直接搜尋：`/ai find 虛顎龍`，或 `/ai find saintsdragons:nulljaw 200`；`/ai 附近 虛顎龍`亦可。名稱含空格可加雙引號。未指定半徑就以玩家為中心搜尋全部已載入、伺服器已傳送的實體，回覆直線距離最近的一個，包含方向、高低差與座標；指定半徑則套用球形距離限制。牆壁、背後或視野外都可查，未載入或未追蹤的實體仍無法查到。直接指令不需登入，也不使用AI額度。

自然語言：`/ai 附近有虛顎龍嗎？`、`/ai 我看不到那隻，幫我指方向`。由既有雲端AI解析實體與半徑（包含前文代詞），產生受驗證的查找要求，交給模組讀取真實位置；不靠固定句型或AI猜座標。自然語言需要登入並使用一次現有問答額度，結果沿用原聊天同步。一般生成、馴服等知識問題仍照常回答。未指定半徑時AI不得自行預設距離。

## 安裝與操作

1. 關閉遊戲，將 `aoi-ai-assistant-1.20.1-0.1.12.jar` 放入實例的 `mods/`，先備份並移除舊版 JAR，避免同一模組重複載入。
2. 進入世界後按 `/`，直接輸入 `/ai 你的問題`。例如 `/ai AE2 要怎麼開始？`。亦可使用 `/小助手 你的問題`。使用原版聊天欄的文字輸入與長度限制，回答只出現在自己的聊天欄，不發至伺服器公開頻道。
3. 首次用 `/ai 登入`，在密碼遮罩視窗輸入攻略網站的遊戲 ID 與網站專用密碼。登入成功自動返回遊戲；該視窗只處理帳號，不用來問問題。不要將密碼寫在指令中。主選單的「AI 小助手」亦只開啟帳號入口。
4. 回覆直接顯示回答文字，不再附加「來源／複製回答／刪除此回覆」操作列。需要查看來源時可手動輸入 `/ai 來源`；刪除指令見下方說明。
5. `/ai 新對話` 開新對話；`/ai 歷史` 顯示可點選的網站共用對話；`/ai 切換 對話ID` 延續既有對話；`/ai more`／`/ai 更多` 重新核對雲端清單並載入下一批；最多300段，點選標題直接在本機切換，不會送至遊戲伺服器。
6. `/ai 同步` 讀取網站變更；`/ai message`／`/ai messages`／`/ai 紀錄` 先同步目前雲端對話再顯示最近訊息；`/ai 更早` 載入更早紀錄；`/ai 狀態` 查詢服務可用情況。
7. 失敗用 `/ai 重試` 沿用原提問 ID；已收到但未同步的回答只重傳，不重新問 AI。`/ai 取消` 取消本機等待；雲端可能仍處理，之後重試仍沿用同一 ID。
8. `/ai 刪除` 先確認再刪目前整段對話；`/ai 刪除 訊息ID` 刪單則。`/ai 保留` 取消刪除確認。`/ai 登出` 清空 AI 的本機紀錄、來源與登入狀態，普通聊天不受影響。

可在「控制 → 按鍵設定 → 王國飛翼 AI 小助手」綁定「開啟 AI 指令聊天欄」，按下會預填 `/ai `。預設未綁定。保留原網站的帳號、證據、免費額度與同步規則。

## 背包、箱子、JEI 與視野辨識（0.1.4）

首次使用請在「控制 → 按鍵設定 → 王國飛翼 AI 小助手」綁定「開啟 AI 指令聊天欄」。預設仍未綁定，建議選擇不與其他模組衝突的功能鍵。

1. 在世界直接開啟 `/ai` 聊天欄，會固定當下主背包、主手、副手及護甲的物品名稱、登錄 ID、數量、耐久與附魔。主手和背包可能是同一件物品，AI 不應重複相加。
2. 要問箱子內容，先開啟箱子，等待物品顯示，再按助手快捷鍵。助手在切換到聊天欄前讀取當下已同步的容器插槽；原箱子介面會關閉，不會自動重開或操作物品。可問 `/ai 這個箱子還缺哪些材料？`。一般箱子、大型箱子及標準容器插槽介面適用；未開啟箱子、閉合背包模組的內部物品、虛擬網路儲存的自訂畫面不保證能讀取。
3. 要問 JEI，先開啟它的物品清單並切換到想問的頁面，再按助手快捷鍵。不必把滑鼠指向特定物品。讀取目前清單頁與配方展示頁的物品圖示，不必懸停；配方圖示保留輸入／輸出角色和配方分組，旋轉材料只記錄當時顯示的選項，不含流體槽或所有替代材料。不掃描全部搜尋結果；JEI 清單不代表玩家持有、已解鎖或已有材料。依目前安裝的 JEI 15.58.0.209 介面做相容讀取，介面變更或無法讀取時附上狀態，不假稱清單是空的。
4. 在世界看向動物、龍或地上的掉落物，再開啟聊天欄，可問 `/ai 畫面上的龍是哪一種？`。不需要準心命中。候選來自遊戲渲染視野、可渲染距離、可見狀態及方塊遮擋近似判斷；最多 96 格、32 個候選，優先保留不同種類，再補同種個體。轉動或移動後不沿用明顯不同的舊視野；沒有近期資料時附上未取得視野的提示。

聊天欄會顯示附帶資料筆數；資料在開啟時固定，輸入期間不持續更新。要換箱子、JEI 頁面或觀察方向，關閉聊天，重新開啟相應畫面再按快捷鍵。重試沿用原快照。物品與畫面資訊獨立附上，原提問仍最多 600 字；過大的清單會記錄省略數，不可據此宣稱沒有其他物品或動物。

此功能是遊戲資料辨識，不是截圖辨識；自訂模型、透明方塊與特殊渲染可能讓視野／遮擋判斷不同。可以辨識註冊的龍或動物種類，但不會根據外觀猜未提供的變種。多隻候選時由 AI 使用名稱、左右與距離釐清。配方、馴服、掉落等玩法仍須有攻略證據，不由看到生物或物品直接推定。

不掃描其他玩家背包或玩家實體姓名；不提交絕對座標、伺服器位址、書中文字或任意完整 NBT。只讀已同步給本機的資料，不替玩家開啟箱子、移動物品或執行遊戲指令。0.1.4 需要雲端的 gameContextVersion 1；未更新時會先提示，避免雲端忽略快照卻消耗問答額度。伺服器仍不需安裝本模組。

## 準心指向提問（0.1.2 起）

1. 在世界中靠近目標，將準心對準方塊、生物／其他實體或地上的掉落物。使用遊戲目前準心的命中結果，沒有額外延長辨識距離，也不穿牆。
2. 按 `/`、`T` 或已綁定的助手快捷鍵開啟聊天欄，輸入 `/ai 這是什麼？`、`/ai 這要用什麼挖？` 或 `/ai 這隻怎麼打？`。
3. 聊天欄上方顯示「AI 目標（已固定）」及名稱／登錄 ID。目標在開啟聊天欄時固定；輸入期間轉動視角或目標移動不會更換它。要換目標，關閉聊天欄、重新對準後再開啟。窄視窗可能截短顯示文字，送出的 ID 仍完整。
4. 沒有命中目標時，畫面顯示未指向方塊或實體，問題照常送出。掉落物使用物品本身的名稱和 ID，實體使用類型名稱，不提交玩家名字、自訂命名、NBT、座標、裝備或伺服器位址。
5. 0.1.2／0.1.3 將目標文字附在問題中；0.1.4 起改為獨立的遊戲快照，不占問題的 600 字額度。登入後延續提問與 `/ai 重試` 都使用原本的固定描述。

0.1.2 當時只需替換客戶端 JAR；0.1.4 的完整遊戲資訊需要同步更新同一 Worker 的快照支援。辨識出目標不代表知識庫一定有該模組的完整攻略。

若裝有 ContingameIME，助手使用其公共編輯狀態介面，只為 `/ai` 及 `/小助手` 問題允許中文輸入，離開助手前綴後恢復既有指令模式；不改 `ingameime.json`。Enter 攔截在其他模組的鍵盤處理之後執行，已被輸入法取消的按鍵不會送出問題。實際 Windows IME 候選視窗仍需遊戲內驗收。

AI 訊息直接插入本機 HUD，不經原版聊天日誌寫入方法；一般伺服器聊天與日誌保留。輸入格式錯誤的 `/ai` 也會在本機攔截，不轉送伺服器。此功能不會自動代替玩家執行遊戲指令。

聊天草稿與待同步訊息僅保留在本次遊戲程序的記憶體中；退出遊戲後未同步內容會消失。密碼不存檔。`config/aoi_assistant-client.toml` 僅包含 HTTPS 服務網址與公開 publishable key。

## 記住登入（0.1.3，Windows）

更新後先正常登入一次，之後重開遊戲會自動恢復登入。預設啟用，不需要額外勾選。只保存用來更新登入的憑證與帳號 UUID，不保存密碼或 access token；檔案為該遊戲實例的 `config/aoi_assistant/session.dpapi`。

保存檔使用 [Windows DPAPI 的目前使用者加密](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)，綁定目前服務設定，不採明文保存。程式重啟後先更新登入憑證並確認帳號核可，再讀取歷史紀錄。每次更新憑證也會更新加密檔，沿用 [Supabase session refresh](https://supabase.com/docs/guides/auth/sessions) 的流程。

- `/ai 登出` 會清除記住的登入並撤銷該次登入。單純關閉遊戲會保留登入。
- 暫時斷網或服務忙碌時保留登入資料，下次請求可以重試；憑證失效、被撤銷或帳號停用時會清除並要求重新登入。
- 保存檔損壞、換了服務設定或無法解密時回到登入流程；設定資料夾不可寫入時，本次仍能使用，狀態會提示無法記住登入。
- 此版的加密保存支援 Windows；其他系統不會改用明文保存。

## 雲端前置條件

必須先發布本專案 `cloud-ai/worker.js` 與 `cloud-ai/client-access.js` 的相容修改，遊戲端才能呼叫原 `/ask`、`/status`、`/forget`。未發布的舊 Worker 會回 403。`player-auth` 已支援無 Origin 的登入請求；資料表與 RLS 沿用現有版本，不需新 SQL 遷移。

正式 Worker 已於 2026-10-09 部署原生入口相容更新，版本 `a250b178-b305-4813-82ee-652b56519c24`；實際 Java HTTPS 與 CORS 檢查均通過。正式帳號的問答、額度與網站／遊戲交替追問仍須進行登入後的驗收。遊戲送問題、對話 UUID 與固定提問 UUID；0.1.2 將準心目標類型、名稱及登錄 ID 附在問題文字中，不新增 API 欄位。不自動提交手持物品、裝備、座標或伺服器資料。`GameContext` 保留型別並未作為 API 欄位送出。

## 建置

需要 JDK 17。Gradle Wrapper 固定 8.8；ForgeGradle 固定 6.0.54；Minecraft 1.20.1 / Forge 47.4.23。所有編譯輸出採 Java 17，不依使用者啟動器的 Java 26 編譯。

```powershell
$env:JAVA_HOME='你的 JDK 17 路徑'
.\gradlew.bat --console=plain verifyClient verifyCommands verifyRememberedLogin build
```

輸出在 `build/libs/`。第一次建置需下載 Forge 與 Minecraft 相依套件；後續可使用 `--offline`。`verifyClient` 是獨立驗證程序，執行帳號、同步、分頁、刪除及故障測試；不連線正式帳號。測試模組與資料不會進發布 JAR。

啟動隔離原生介面驗證：

```powershell
.\gradlew.bat --console=plain -PguiVerification runClient
```

驗證客戶端會隱藏視窗、自動操作、截圖後退出。畫面與結果放在 `run/`，使用測試聊天資料，不代表真實帳號或整合包驗收。一般開發可用 `runClient` 手動操作。

後端回歸：在網站目錄執行 `node --test cloud-ai/*.test.js`。

## 同步與限制

- Supabase REST 每次附 JWT 與本人 user_id 篩選；權限由原 RLS 強制執行。使用公開金鑰，絕不使用 service_role。
- 問題先寫入雲端，再呼叫同一 Worker。UUID 固定；遇到重複 ID 必須核對雲端訊息角色、文字及來源，不能盲目視作成功。
- 回答寫入失敗會保留固定助手 UUID。重新上傳先確認對話及原提問仍存在，已刪除的對話不會自動重建。
- 刪除先 `/forget`，再刪本人資料表；刪問句會更新對話標題。失敗不從本機假裝移除。網站的 history epoch 與遊戲的取消 epoch 共同避免過時回答恢復。
- 所有網路工作在專用背景執行緒；UI 更新回 Minecraft 主執行緒。取消等待可能不會中止雲端模型，因此重試須沿用 UUID。
- 回覆內容只作文字顯示，控制字元與格式碼經處理，來源容錯解析；不執行遠端內容。唯一外部網站入口固定至官方攻略網址並要求確認。
- 使用 token refresh 並輪替 refresh token；401 刷新一次仍失敗或 403 會清除憑證。供應商與配額錯誤不會產生成功的助手訊息。
- 首版是手動／開啟頁面的更新，不是即時推播。兩端同時在同一段對話提問不保證完全線性。資料讀寫與 `/ask` 分屬現有服務，跨裝置刪除的極小競態只能以存在檢查與 Worker epoch 緩解，未宣稱資料庫與模型的原子交易。
- 原生 Forge GUI 測試不取代實際整合包的 IME、GUI 模組、多人連線與真實雲端帳號驗收。
